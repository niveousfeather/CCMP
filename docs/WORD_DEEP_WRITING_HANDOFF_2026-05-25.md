# NexusAI Word / Deep Writing Project Handoff

## 2026-05-25 WORD-CONTENT-PIPELINE-01

This handoff was updated for the Word content pipeline boundary fix.

### Root Cause Fixed

The bug where a request such as:

```text
帮我生成一个小学三年级语文课程的教案
```

could produce 三维动画 / 建模 / 材质 / 灯光 / 渲染 / 关键帧 content had two concrete causes:

1. Deep Writing section drafts were generated by `composeDeepWritingDraft()`, and the lesson-plan fallback defaulted to `三维动画课程`.
2. Final deep-writing docx rendering called `generateDocx()`, which rerouted any `lesson_plan` content to `composeLessonDocumentPlan(request)`, replacing completed sections with deterministic lesson template content.

### New Boundary

The Word pipeline is now:

```text
user request
-> runtime intent / WordWriteModeClassifier
-> export_existing: existing content goes directly to Word Engine rendering
-> compose_simple / compose_deep: Deep Writing generates sections first
-> completed Deep Writing sections become generated_content
-> Word Engine renders layout/docx only
```

Word Engine owns formatting and package generation:

- title hierarchy
- section mapping
- fonts and spacing
- header/footer
- table rendering
- theme color
- docx package

Word Engine must not own from-scratch subject content for write requests.

### Topic Safety

New helper:

```text
lib/word-engine/topic-profile.ts
```

It extracts topic profile fields such as:

```text
小学三年级语文课程 -> subject=语文, grade=小学三年级, domain=primary_language
三维动画课程 -> subject=三维动画, domain=animation_course
```

`DeepWritingTaskMemory` now records `topicFingerprint`, `subject`, `grade`, and `domain`.

Resume is only allowed for explicit resume phrases, and a resume phrase that introduces a different explicit topic throws `TOPIC_FINGERPRINT_MISMATCH` instead of reusing stale sections.

### Topic Consistency Guard

New guard:

```text
lib/word-engine/validate-topic-consistency.ts
```

Generated docx rendering checks the request and generated content before completing a docx. For primary-language requests, animation leakage terms such as 三维动画、建模、材质、灯光、渲染、关键帧、Maya、Blender block completion.

### Tests Added

New regression:

```text
scripts/agent-runtime/check-word-content-pipeline.ts
```

Expected output:

```text
Word content pipeline checks passed. 20/20 PASS.
```

It covers engine rejection of unmarked write-from-scratch, export_existing fast docx, compose_simple/deep deep-writing routing, topic extraction, primary-language no-leak checks, animation allowance, cross-topic memory isolation, resume guard, completed-section docx rendering, payload safety, and no fake search sources.

### Updated Existing Checks

`check-word-lesson-plan.ts`, `check-word-quality.ts`, and `check-word-style.ts` now follow the new boundary:

- from-scratch lesson plans enter Deep Writing
- generated lesson content may be rendered by Word Engine
- clear topics without generated/source content no longer fast-render docx

### Explicit Non-Changes

This phase did not modify capability-map, smart-tools, dashboard layout, Excel Engine, Academic PPT, services, data, prisma, or chat UI/editor components.

## 31D-WORD-FIX Summary

### Problem

When the frontend sent:

```text
contentMode: "write"
```

and the user asked:

```text
帮我写一个三维动画教学课程的教案
```

or:

```text
帮我写一个三维动画教学课程的教案，64 个课时，2000 字
```

the backend routed to `word-adapter` and then to the fast `word-engine` path. The generated Word file returned quickly, but the body looked like a thin generic document:

```text
文档概述
背景与目标
主要内容
使用建议
```

It did not contain a proper lesson-plan structure.

### Root Cause

The Word engine previously recognized only these document kinds:

```text
summary / report / plan / training / general
```

It did not recognize `lesson_plan`, so lesson-plan requests were treated as `general`.

### Fix

Added a real `lesson_plan` document kind and routed lesson-plan requests to a dedicated thin adapter around the existing professional lesson-plan logic.

Core files:

```text
lib/word-engine/types.ts
lib/word-engine/detect-word-attributes.ts
lib/word-engine/compose-word-content.ts
lib/word-engine/compose-lesson-plan-content.ts
lib/word-engine/generate-docx.ts
lib/word-engine/index.ts
```

Regression script:

```text
scripts/agent-runtime/check-word-lesson-plan.ts
```


Simple notices and ordinary Word advice are not classified as `lesson_plan`.

## 64 Class Hours And 2000 Words

For:

```text
帮我写一个三维动画教学课程的教案，64 个课时，2000 字
```

current behavior:

- The request does not enter `general`.
- The request enters `lesson_plan`.
- The body includes `64 课时`.
- The body includes a staged class-hour arrangement.

The staged arrangement includes:

- 课程导入与软件基础
- 三维建模基础
- 材质、灯光与渲染
- 动画规律与关键帧制作
- 角色/场景动画综合训练
- 项目作品制作与展示评价

The current fast Word path does not strictly guarantee an exact 2000-character count, but it avoids returning a one-page thin template. Future work can route long lesson-plan requests to Deep Writing when exact length pressure matters.
