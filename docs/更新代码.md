# NexusAI 服务器版本更新指南

本文档用于日常版本更新。目标是：只更新代码，不删除用户数据、不覆盖服务器配置、不重新配置自建搜索。

适用场景：

- 已经完成首次部署
- 宝塔 Node 项目已经能正常运行
- 数据库、`.env`、OSS、自建搜索已经配置好
- 后续只是上传新版本代码

## 一、更新原则

每次更新只做这件事：

```text
替换代码 -> 安装依赖 -> 生成 Prisma Client -> 执行迁移 -> 构建 -> 重启 Node 项目
```

不要做这几件事：

```bash
npx prisma migrate reset
npx prisma db push --force-reset
rm -rf /www/wwwroot/项目目录
删除 .env
覆盖数据库文件
删除 /www/server/searxng
删除 Docker 里的 searxng 容器
```

## 二、必须保留的文件和目录

这些内容是服务器持久化数据或服务器专属配置，更新版本时不要覆盖、不要删除。

| 路径 | 是否保留 | 原因 |
| --- | --- | --- |
| `/www/wwwroot/你的项目/.env` | 必须保留 | 服务器环境变量、密钥、数据库地址、OSS 配置 |
| `/www/wwwroot/你的项目/prisma/*.db` | 必须保留 | 如果 SQLite 数据库放在项目目录，这里就是用户数据 |
| `/www/wwwroot/你的项目/prisma/*.db-journal` | 保留 | SQLite 临时文件，停服备份时一般不会存在 |
| `/www/wwwroot/你的项目/public/mock-storage` | 建议保留 | 如果曾经启用本地存储兜底，里面可能有生成文件 |
| `/www/server/searxng` | 必须保留 | 自建联网搜索 SearXNG 配置和缓存 |
| Docker 容器 `searxng` | 必须保留 | 自建搜索服务 |
| 宝塔 Node 项目配置 | 必须保留 | 端口、启动命令、运行目录 |
| 宝塔 Nginx / SSL / 反向代理配置 | 必须保留 | 域名、HTTPS、反代超时 |

更推荐把数据库放到项目目录外，例如：

```text
/www/data/nexusai/prod.db
```

然后 `.env` 使用：

```env
DATABASE_URL="file:/www/data/nexusai/prod.db"
```

这样以后更新项目目录时，数据库不会被误覆盖。

## 三、可以覆盖的代码文件和目录

这些是应用代码，更新版本时可以覆盖：

| 路径 | 是否覆盖 | 说明 |
| --- | --- | --- |
| `app/` | 覆盖 | Next.js 页面和 API |
| `components/` | 覆盖 | 前端组件 |
| `lib/` | 覆盖 | 后端服务、Agent、工具链 |
| `public/` | 覆盖，但注意保留 `public/mock-storage` | 静态资源 |
| `scripts/` | 覆盖 | 验证脚本、维护脚本 |
| `prisma/schema.prisma` | 覆盖 | 数据库模型定义 |
| `prisma/migrations/` | 覆盖或新增 | 数据库迁移文件 |
| `.env.example` | 覆盖 | 示例环境变量，不影响真实 `.env` |
| `package.json` | 覆盖 | 依赖和命令 |
| `pnpm-lock.yaml` | 覆盖 | 锁定依赖版本 |
| `next.config.ts` | 覆盖 | Next 配置 |
| `middleware.ts` | 覆盖 | 登录鉴权中间件 |
| `tailwind.config.ts` | 覆盖 | 样式配置 |
| `tsconfig.json` | 覆盖 | TypeScript 配置 |
| `README.md` / `docs/` | 覆盖 | 文档 |

这些不需要上传，服务器会自己生成：

```text
node_modules
.next
tsconfig.tsbuildinfo
```

## 四、推荐方式：Git 更新

这是后续最省事的方式。

进入服务器项目目录：

```bash
cd /www/wwwroot/nexusai
```

更新代码：

```bash
git pull
```

安装依赖：

```bash
pnpm install --frozen-lockfile
```

生成 Prisma Client：

```bash
pnpm exec prisma generate
```

执行数据库迁移：

```bash
pnpm exec prisma migrate deploy
```

构建：

```bash
pnpm build
```

重启宝塔 Node 项目：

```text
宝塔 -> Node 项目 -> 找到 NexusAI -> 重启
```

## 五、手动上传 ZIP 更新

如果暂时不用 Git，可以继续用上传 ZIP 的方式，但不要全删目录。

### 1. 本地打包时排除

不要把这些打包上传：

```text
node_modules
.next
.env
.git
tsconfig.tsbuildinfo
prisma/*.db
prisma/*.db-journal
public/mock-storage
```

### 2. 服务器上传

建议上传到临时目录，例如：

```text
/www/upload/nexusai-new
```

不要直接覆盖运行中的项目目录。

### 3. 备份服务器关键数据

进入项目目录：

```bash
cd /www/wwwroot/nexusai
```

备份 `.env`：

```bash
cp .env .env.bak.$(date +%Y%m%d%H%M%S)
```

如果数据库在项目目录里，备份数据库：

```bash
cp prisma/prod.db prisma/prod.db.bak.$(date +%Y%m%d%H%M%S)
```

如果你的数据库文件叫 `dev.db`，就备份：

```bash
cp prisma/dev.db prisma/dev.db.bak.$(date +%Y%m%d%H%M%S)
```

### 4. 覆盖代码

只把新版本里的代码目录和配置文件复制到项目目录，不复制 `.env` 和数据库。

可覆盖：

```text
app
components
lib
public
scripts
docs
prisma/schema.prisma
prisma/migrations
package.json
pnpm-lock.yaml
next.config.ts
middleware.ts
tailwind.config.ts
tsconfig.json
postcss.config.js
README.md
.env.example
```

不要覆盖：

```text
.env
prisma/*.db
public/mock-storage
```

### 5. 执行更新命令

```bash
cd /www/wwwroot/nexusai
pnpm install --frozen-lockfile
pnpm exec prisma generate
pnpm exec prisma migrate deploy
pnpm build
```

然后重启宝塔 Node 项目。

## 六、如果新版本增加了环境变量

不要直接用 `.env.example` 覆盖 `.env`。

正确做法：

1. 打开新版本 `.env.example`
2. 对比服务器 `.env`
3. 只把新增变量手动追加到服务器 `.env`
4. 填入真实值
5. 重启 Node 项目

示例：

```bash
nano .env
```

保存后：

```text
宝塔 -> Node 项目 -> 重启
```

## 七、数据库迁移规则

正常更新只执行：

```bash
pnpm exec prisma migrate deploy
```

不要执行：

```bash
pnpm exec prisma migrate reset
pnpm exec prisma db push --force-reset
```

如果 `migrate deploy` 报错，先停止，不要强行 reset。先备份数据库，再排查迁移。

## 八、自建联网搜索更新规则

SearXNG 独立于网站项目，不需要每次重新部署。

保留：

```text
/www/server/searxng/config/settings.yml
/www/server/searxng/data
Docker 容器 searxng
```

验证自建搜索：

```bash
curl "http://127.0.0.1:8080/search?q=重庆今天温度&format=json&language=zh-CN"
```

看到：

```json
"results": [...]
```

说明可用。

如果只是更新网站代码，不需要动 SearXNG。

## 九、更新后验证清单

每次更新后按顺序验证：

1. 打开登录页：

```text
https://你的域名/login
```

2. 登录管理员账号，确认能进入工作台。

3. 打开工作台，确认今日额度、模型状态正常。

4. 打开 Nexus Agent，测试普通对话：

```text
你好
```

5. 测试联网对话：

```text
重庆今天温度
```

6. 测试图片生成。

7. 测试视频历史记录能打开。

8. 测试知识图谱生成。

9. 打开历史记录页面，确认旧数据还在。

10. 查看宝塔 Node 项目日志，确认没有连续 500 / 502 / 504。

## 十、回滚方式

如果新版本有问题：

1. 停止 Node 项目
2. 恢复上一版代码
3. 保留当前 `.env`
4. 不回滚数据库，除非明确知道迁移导致数据问题
5. 重新执行：

```bash
pnpm install --frozen-lockfile
pnpm exec prisma generate
pnpm build
```

6. 重启 Node 项目

如果数据库迁移已经执行，并且必须回滚数据库，只能恢复更新前备份的数据库文件。

## 十一、推荐的服务器目录结构

建议逐步整理成这样：

```text
/www/wwwroot/nexusai          # 网站代码
/www/data/nexusai/prod.db     # SQLite 数据库
/www/server/searxng           # 自建搜索
/www/backup/nexusai           # 手动备份
```

这样后续更新 `/www/wwwroot/nexusai` 时，用户数据库和自建搜索都不会被影响。

## 十二、最短更新命令

如果使用 Git，日常更新就是：

```bash
cd /www/wwwroot/nexusai
git pull
pnpm install --frozen-lockfile
pnpm exec prisma generate
pnpm exec prisma migrate deploy
pnpm build
```

然后在宝塔里重启 Node 项目。
